# Выбранная модель — закон (никакой молчаливой подмены)

## Что было не так

В шапке чата стояла, например, `glm-5.3`, а отвечала `zai/glm-4.5-flash`. Причин было две,
и они складывались.

1. **Сервер расширял план моделей даже при ручном выборе.**
   `buildModelPlan()` для явно выбранной модели возвращал `expandOnFailure: true`.
   Если провайдер отвечал 401/403/404/429/5xx или обрывал сеть *до первого видимого
   токена*, `callModelAutopilot()` строил `expandedPlan()` из каталога и отвечал
   **другой** моделью. В чате это выглядело как обычный ответ выбранной модели,
   а на вопрос «какая ты модель» приходил honest-ответ уже другой модели —
   отсюда и расхождение.
2. **Фронтенд молча сбрасывал выбор на «Авто».**
   `modelsSlice.loadModels()` при живом провайдере, но отсутствующей в каталоге
   модели делал `selected = { ...AUTO_MODEL }`. Следующий вопрос уходил уже
   в режиме автовыбора, хотя пользователь ничего не менял.

## Что стало

**Модель выбирает агент только в режиме «Авто».** Явный выбор закрепляется
флагом `locked: true` и не может быть заменён ничем.

| Файл | Изменение |
| --- | --- |
| `server/native/autopilot.mjs` | Явный выбор → `{ locked: true, expandOnFailure: false }`. `runFallbackPlan()` при `locked` не переходит к следующему кандидату, а помечает ошибку `modelLocked` и готовит текст `publicMessage`. `callModelAutopilot()` не расширяет план при `locked`. `promoteModelPlan()` сохраняет замок и не наращивает список кандидатов. Новые хелперы `modelFailureReason()` и `lockedModelMessage()`. |
| `server/native/providers.mjs` | `publicProviderErrorMessage()` отдаёт готовый `err.publicMessage` вместо generic-маски. Текст `PUBLIC_MODEL_UNAVAILABLE` больше не обещает «агент возьмёт другую». |
| `server/native/agent.mjs` | Отказ закреплённой модели уходит в чат как есть (без префикса «Ошибка агента»). `info.autopilot` теперь честный: `enabled: !locked`, `mode: 'locked' \| 'auto'`, `requested`. |
| `server/native/durable-jobs.mjs` | `locked` сохраняется в файле задания, поэтому восстановленный после перезапуска ход тоже не подменит модель. |
| `src/store/slices/modelsSlice.ts`, `src/store/types.ts` | Выбор больше не сбрасывается на «Авто». Появился флаг `selectedModelMissing`. «Авто» ставится только когда выбора не было вообще. |
| `src/components/ModelSelector.tsx` | Пропавшая из каталога модель показывается сама (жёлтая точка + «нет в каталоге»), а не «Выбрать модель»/«Авто». В меню добавлено пояснение про ручной режим. |
| `src/api/eventGuards.ts` | Клиентский текст ошибки синхронизирован с сервером. |

## Что теперь видит пользователь

Вместо ответа чужой модели в чат приходит одна строка с причиной:

```
Модель «zai/glm-5.3» не выполнила запрос: на аккаунте провайдера нет баланса или
исчерпана квота. Автовыбор выключен, потому что модель задана вручную. Выберите
другую модель в списке сверху или переключитесь на «Авто» — тогда модель подберёт агент.
```

Распознаются: нет баланса/квоты (402), отклонённый ключ и нет доступа (401/403),
модели не существует или она снята (404), лимит запросов (429), ошибка сервера (5xx),
обрыв сети/TLS, таймаут провайдера.

В режиме «Авто» поведение не изменилось: агент по-прежнему сам ранжирует каталог
и берёт следующую модель при сбое до начала ответа.

## Тесты

`tests/autopilot.test.mjs`:

- выбранная вручную модель никогда не подменяется другой (второй кандидат не вызывается);
- в режиме «Авто» переход на следующую модель по-прежнему работает;
- `locked`-план остаётся закреплённым на всех шагах хода;
- причины отказа формулируются человеческим языком, без брендов и ссылок;
- замок соблюдается во всей цепочке: рантайм, чат, перезапуск.

`src/store/slices/modelsSlice.test.ts`: выбор не подменяется при пропаже модели из
каталога (выставляется `selectedModelMissing`), «Авто» ставится только при отсутствии выбора.

Запуск: `node --test tests/*.test.mjs` (316 тестов, все проходят) и `npx vitest run`
для фронтенда (нужны установленные `node_modules`).
