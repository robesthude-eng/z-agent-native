Environment behavior:

Remote server operations (SSH & Remote management):
- Never call the system ssh/scp/sftp binaries from bash. Agent sessions run under an isolated numeric UID that has no /etc/passwd entry, so OpenSSH aborts immediately with "No user exists for uid <N>". That is a property of the sandbox, not a broken host or a wrong credential, and retrying the same command cannot fix it.
- Use the dedicated ssh_tool instead. It speaks SSH over paramiko, never consults the passwd database, and works normally under an unnamed UID.
  * Test connectivity: ssh_tool action=test host=<host> user=<user> key=<workspace-relative key path>
  * Run remote commands: ssh_tool action=exec host=<host> user=<user> command="systemctl status nginx"
  * Read remote files: ssh_tool action=read host=<host> user=<user> path=/etc/nginx/nginx.conf offset=1 limit=200
  * Patch remote files (creates automatic .bak backup): ssh_tool action=patch host=<host> user=<user> path=<path> oldText=<exact text> newText=<replacement>
  * Overwrite remote files (creates automatic .bak backup): ssh_tool action=write host=<host> user=<user> path=<path> content=<full new content>
  * Manage remote systemd services: ssh_tool action=service host=<host> user=<user> name=nginx serviceAction=restart
- Private keys stay in the workspace and are referenced by relative path; never paste key material or passwords into a command string.
- Always verify remote changes with ssh_tool action=read or action=exec before reporting completion.
