# Исправления от 3 октября 2026

## Завершение работы агента

Исправлен сценарий, похожий на скриншот: после осмотра пустого воркспейса
модель давала итоговый ответ, но runtime ошибочно требовал продолжить проверки.
Команды bash теперь сопровождаются ограниченным по времени и объёму сравнением
метаданных файлов до и после запуска. Команда осмотра без изменений больше
не считается редактированием только потому, что её нет в списке известных
команд чтения. При неполном сканировании сохраняется консервативная обработка.

Итоговый запрос дополнительных данных пользователя завершает текущий ход со
статусом «Нужны данные» и переводит сессию в idle. Незакрытый план после осмотра
без изменений больше не запускает новые операции автоматически; результат
такого плана остаётся частичным. Реальные изменения по-прежнему требуют проверки.
Данные о фактических изменениях сохраняются в истории инструментов для восстановления.

Убраны шаблонные утверждения «всё проверено / система работает штатно» без
подтверждающих результатов. Отмена, частичное выполнение и недоступность запуска
проверок отражаются в итоговом отчёте.

## Инструменты и медиа

- SSH: приведены в соответствие схема вызова, обработчик и Python CLI.
  Поддержаны key/keyPath, path/remotePath, name/service, точечная замена
  oldText/newText, reload и journal/logs с количеством строк.
- Ненулевой код завершения SSH считается ошибкой для всех действий.
  Обработан EPIPE при раннем выходе дочернего процесса; отмена принудительно
  завершает зависший процесс после SIGTERM.
- Пароль sudo поступает через stdin, включая пароль из переменной окружения.
  Он не вставляется в текст удалённой команды. Ключи SSH-хостов сохраняются
  в known_hosts внутри домашнего каталога сессии (доверие при первом подключении).
- Удалённая запись и замена текста сначала создают резервную копию и временный
  файл, затем атомарно заменяют основной файл. Ошибка записи не удаляет оригинал.
  Требуется поддержка POSIX rename на SFTP-сервере.
- Диагностика учитывает массив kinds; запуск тестов учитывает framework и command.
  Фильтр тестов передаётся одним аргументом. Git учитывает count/ref и limit/rev.
- Изображения и речь используют протокол настроенного канала, а не его имя/ID.
  Неверный или отключённый явно выбранный канал больше не заменяется другим.
  Для нескольких каналов и для Google нужно указывать точную модель.
- Исправлено сохранение изображений и аудио: фактический путь, размер, MIME-тип,
  чтение файлов-референсов. Ранее объект пути превращался в имя «[object Object]».

## Настройки и интерфейс

Новые установки по умолчанию используют ограниченный профиль hardened.
Генератор .env создаёт случайный код регистрации наряду с ключами и токеном метрик.
Для личного сервера доступны явные профили:

```bash
npm run prod:env:init -- --profile=trusted
npm run prod:env:init -- --profile=unrestricted
```

trusted включает Интернет, SSH, установщики и терминал; unrestricted дополнительно
включает sudo в executor и доступ к файлам с учётными данными. Существующий .env
генератор не перезаписывает. Параметры действующей установки автоматически не меняются.

Документы preview получают CSP sandbox даже при открытии прямой ссылкой.
Исправлены три ошибки линтера в компонентах чата; сохранена прокрутка клавиатурой.

## Состав и применение

Это обновлённые исходники, а не установленная версия на сервере. В архиве нет
node_modules, dist, баз данных, пользовательских воркспейсов и секретного .env.
При обновлении существующей установки сохраните её .env и постоянные тома,
замените исходники и пересоберите контейнеры согласно README.
